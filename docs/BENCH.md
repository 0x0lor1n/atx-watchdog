# Pro Micro как кнопка питания NAS: сборка на макетке

Два этапа: сначала реле-плата (полярность кнопки не важна, ошибка ничего не
сожжёт), потом то же самое на BC547 — это финальная схема, её потом паяем.
Принципиальная схема PoC: [poc/schematic.svg](poc/schematic.svg). Разводка макеток: [poc/wiring.svg](poc/wiring.svg) и [final/wiring.svg](final/wiring.svg). Рядом с каждой лежит `.png` — для телеги и телефона.
Раскладка макетки — `fizzel-poc` / `fizzel-final` (см. ниже). Колонки/ряды
на картинке — предложение, не обязательство: важны цепи.

## Команды devshell

Всё ниже — из корня репы, внутри `nix develop` (или `direnv allow` один раз).

| команда | что делает |
|---|---|
| `flash-relay [port]` | собрать и прошить прошивку этапа A (pin 4 active LOW) |
| `flash-transistor [port]` | то же для этапа B (pin 4 active HIGH) |
| `fizzel-poc` | открыть `docs/poc/bench.fzz` в Fritzing |
| `fizzel-final` | открыть `docs/final/bench.fzz` в Fritzing |
| `picocom -b 115200 --omap crlf --echo /dev/ttyACM0` | консоль к Pro Micro |
| `render-docs` | перерисовать `docs/*/{schematic,wiring}.{svg,png}` после правки `src/schematic/poc.py` или `wiring.d2` |
| `nix flake check` | sim прошивки, NixOS VM, Fritzing-lint макеток, свежесть `docs/` |
| `nix build .#bench-fzz` | перегенерировать `bench.fzz` из `src/fritzing/gen.py` |

`port` по умолчанию `/dev/ttyACM0`. `avrdude` тоже в шелле, если надо руками.

## Детали

- Pro Micro 5 V / 16 MHz (вторая), USB-кабель
- макетка + провода Dupont: папа-папа, папа-мама (на JFP1/JCOM1 и гребёнку реле)
- реле-плата Waveshare RPi Relay Board (этап A)
- 3× BC547 (Q1, Q2, запасной), 1× 1N4148
- резисторы: 3× 10k (R1, R2, R4), 1× 2.2k (R3)
- мультиметр

BC547: плоской стороной с надписью к себе, ноги вниз — слева направо
**C B E**. (PN2222A наоборот: E B C — не путать, бери BC547.)

## Шины макетки

- Верхняя «+» = 5 V, верхняя «−» = GND.
- Pro Micro VCC → «+», Pro Micro GND → «−».
- Пока стенд на столе — питание по USB от ноутбука. В NAS — 5VSB с ATX pin 9
  на «+», а USB не подключать одновременно с 5VSB.

## 0. Прошивка (один раз на этап)

```
flash-relay          # этап A
flash-transistor     # этап B
```

Скрипт сам переводит плату в загрузчик: открывает порт на 1200 бод, Caterina
сбрасывается и на ~8 с появляется как `2341:0036`, туда и льётся
(`bootloader on /dev/ttyACM0`). RST трогать не надо. Если на плате нет
живого скетча (пустая или битая прошивка), скрипт напишет
`no bootloader: short RST to GND twice now` — тогда дважды коротко замкни
RST на GND, у тебя 15 с.

`Permission denied` на `/dev/ttyACM0` — пользователь не в группе `dialout`
в текущей сессии: перелогиниться или `sg dialout -c 'flash-relay'`.
Порт: `ls /dev/ttyACM*` до и после подключения, если их несколько.

Консоль для всех тестов:

```
picocom -b 115200 --omap crlf --echo /dev/ttyACM0
```

После прошивки Pro Micro перечисляется заново — picocom запускать уже после
`flash-*`, а перед следующей прошивкой закрыть (Ctrl-A Ctrl-X), иначе
1200-бодный сброс не пройдёт.

Команды (Enter в конце): `PING` → `pong` (кнопку не трогает), `PRESS`
(0,3 с), `HOLD` (6 с), `POWEROFF`, `REBOOT`, `STATUS` (состояние
watchdog). Каждую принятую строку прошивка
печатает как `usb: ...` или `com: ...`. Выход из picocom: Ctrl-A Ctrl-X.

## Этап A — реле-плата

### A1. Pro Micro + реле, без NAS

| гнездо реле-платы | куда |
|---|---|
| pin 1 (3V3) | шина «+» |
| pin 2 (5V) | шина «+» |
| pin 6 (GND) | шина «−» |
| pin 37 (CH1) | Pro Micro pin 4 |

Relay_JMP: перемычка на CH1 (IN_CH1–P25) обязательна. По схеме Waveshare
гнездо 37 доходит до входа CH1 только через неё. Гнездо 1 питает оптопару
(3.3V → 1k → PC817 → LED1 → IN_CH1); 5 V туда допустимо.

`PRESS` → щелчок, LED1 мигает. `HOLD` → LED1 горит 6 с. Сигнал на 37 есть,
а LED1 не горит — нет перемычки CH1 или гнезда 1.

Мультиметр в прозвонке на клеммнике CH1: COM–NO звенит только во время
`HOLD`.

### A2. Инвертор (RS-232 → TTL)

На макетке, по poc/wiring.svg:

1. Q1 BC547 в макетку, три ноги в три разных столбца.
2. R1 10k: свободный столбец («вход SOUT») → база Q1.
3. D1 1N4148: полоска (катод) → база Q1, другой конец → «−».
4. Эмиттер Q1 → «−».
5. R2 10k: коллектор Q1 → «+».
6. Коллектор Q1 → Pro Micro pin 0 (RX).

Проверка без NAS: мультиметр на коллекторе ≈ 5 V. Провод из столбца
«вход SOUT» на «+» на секунду → коллектор ≈ 0 V. Вернул → снова 5 V.

### A3. Подключение к NAS

NAS обесточен (выключатель на БП). Кнопку корпуса с JFP1 PWR SW снять.

| провод | откуда | куда |
|---|---|---|
| кнопка 1 | JFP1 pin 6 | клеммник CH1 COM |
| кнопка 2 | JFP1 pin 8 | клеммник CH1 NO |
| земля | JCOM1 pin 5 | шина «−» |
| данные | JCOM1 pin 3 | столбец «вход SOUT» |

Перед этим сверить распиновку JCOM1 по мануалу платы (3 = SOUT, 5 = GND,
10 — без штырька, это ключ).

1. Включить БП. `PRESS` → NAS стартует.
2. В BIOS: Advanced → Super IO → Serial Port = **Enabled**.
3. Загрузилась ОС: мультиметр JCOM1 pin 3 относительно pin 5 = −5…−12 V.
4. Проверка канала с NAS:
   ```
   sudo stty -F /dev/ttyS0 9600 cs8 -cstopb -parenb raw -echo
   printf '\nPING\n' | sudo tee /dev/ttyS0
   ```
   В picocom на ноутбуке: `com: PING` и `pong`.
5. `HOLD` из picocom на зависшем после poweroff NAS → гаснет.
6. Подключить `nixosModules.default` в конфиг NAS → `sudo nixos-rebuild boot` → загрузиться
   → `sudo poweroff`. В picocom: `com: POWEROFF`, через ~9 с NAS гаснет.
   Потом `sudo reboot`: гаснет и включается сам.

## A4. Watchdog (после A3.6, модуль уже стоит)

Модуль шлёт `ALIVE` раз в минуту — в picocom видно `com: ALIVE`.
`STATUS` → `watchdog: armed, last ALIVE s ago: N`.

1. Имитация зависания: на NAS
   ```
   sudo systemctl kill -s STOP nas-power-button-heartbeat
   ```
   (STOP — процесс замирает молча, как при настоящем зависании; обычный
   `systemctl stop` шлёт DISARM и watchdog не сработает — так и задумано.)
2. Через 5 мин в picocom: `watchdog: no ALIVE, hold, gap, press`, NAS
   гаснет на ~9 с и стартует сам.
3. После загрузки снова `com: ALIVE` раз в минуту — взвёлся заново.

Watchdog молчит, пока не пришёл первый `ALIVE`, и разряжается после
POWEROFF/REBOOT/DISARM и после своего срабатывания. Поэтому BIOS, загрузка
и выключенный NAS не трогаются, а NAS, который не смог загрузиться,
дёргается один раз, без цикла.

## Этап B — BC547 вместо реле (финальная схема)

Реле-плату снять. `flash-transistor`.

### B1. Найти «горячий» пин PWR SW

NAS под питанием (стоит, выключен). Мультиметр, постоянка: «−» щупа на
корпус/винт платы, «+» по очереди на JFP1 pin 6 и pin 8. Где ≈ 3,3 V — тот
«горячий», второй ≈ 0 V (земля). Записать.

### B2. Ключ на макетке (по final/wiring.svg)

1. Q2 BC547 в три свободных столбца.
2. R3 2.2k: Pro Micro pin 4 → база Q2.
3. R4 10k: база Q2 → «−» (держит Q2 закрытым, пока Pro Micro
   перезагружается или прошивается).
4. Эмиттер Q2 → «−».
5. Коллектор Q2 → «горячий» пин JFP1.
6. Второй пин PWR SW не подключать: земля уже общая через JCOM1 pin 5.

Проверка без NAS: мультиметр в прозвонке/омах между коллектором и «−»
— обрыв; во время `HOLD` — почти ноль.

### B3. Повтор A3 (пункты 1, 5, 6) и A4

Если всё как на реле — схема окончательная, можно паять.

## Что смотреть, если не работает

- Реле/Q2 не реагирует на `PRESS`: в picocom нет `usb: PRESS` → не тот
  порт или не прошилось; есть → проводка pin 4.
- Нет `com: ...` при отправке с NAS: Serial Port в BIOS, распиновка JCOM1,
  коллектор Q1 в покое должен быть 5 V (если 0 — инвертор собран неверно
  или SOUT подан на коллектор).
- `com:` с мусором: скорость — должна быть 9600 с обеих сторон.
